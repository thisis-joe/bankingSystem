# 실행과 SDUI 확인 방법

## 1. 이 문서의 목적

이 문서는 현재 프로젝트를 실제로 실행하고, SDUI 관리자 화면과 JSON 화면 정의를 어떻게 확인하면 되는지 바로 따라할 수 있게 정리한 참고 문서다.

특히 이번 프로젝트에서는 `서버가 화면 구조를 JSON으로 내려주고`, `브라우저가 그 JSON을 받아 화면을 그리는 구조` 를 학습하는 것이 중요하다.
그래서 단순히 실행 명령만 적는 것이 아니라, 어떤 순서로 보면 SDUI가 잘 이해되는지도 같이 적는다.

## 2. 어디에서 실행하는가

프로젝트 루트 경로는 아래다.

`C:\SSAFY\joseph\workspaces\BankingSystem`

실행은 이 경로에서 해야 한다.

## 3. 실행 명령

터미널에서 아래 순서로 실행한다.

```powershell
cd C:\SSAFY\joseph\workspaces\BankingSystem
.\gradlew.bat :bootstrap:bootRun
```

정상적으로 실행되면 Spring Boot 애플리케이션이 올라가고, 기본 포트 `8080` 에서 접속할 수 있다.

## 4. 어떤 주소를 열어야 하는가

애플리케이션이 뜬 뒤 브라우저에서 아래 주소를 열면 된다.

### 4.1 SDUI 화면

[http://localhost:8080/sdui-admin/index.html](http://localhost:8080/sdui-admin/index.html)

이 주소는 실제 관리자 화면이다.
브라우저가 서버에서 내려준 JSON 화면 정의를 읽어서 한 페이지 운영 화면으로 렌더링한다.

### 4.2 SDUI JSON 화면 정의

[http://localhost:8080/api/v1/admin/screens/core-banking-overview](http://localhost:8080/api/v1/admin/screens/core-banking-overview)

이 주소는 화면 그 자체가 아니라 `화면 설명서` 에 가깝다.
즉, 서버가 아래 내용을 JSON으로 내려준다.

- 화면 ID
- 화면 제목
- 블록 종류
- 표 컬럼
- 타임라인 항목
- 액션 목록

이 JSON을 먼저 보고, 그 다음 실제 화면을 보면 SDUI 개념이 훨씬 잘 들어온다.

### 4.3 H2 콘솔

[http://localhost:8080/h2-console](http://localhost:8080/h2-console)

현재 프로젝트는 학습용 실행을 위해 H2 메모리 DB를 사용하도록 설정되어 있다.

접속 정보는 아래와 같다.

- JDBC URL: `jdbc:h2:mem:bankingsystem`
- User Name: `sa`
- Password: 비움

## 5. 가장 추천하는 확인 순서

SDUI를 이해하려면 아래 순서로 보는 것이 가장 좋다.

1. 먼저 JSON 화면 정의 API를 연다.
2. JSON 안에서 `screenId`, `title`, `blocks`, `component` 를 본다.
3. 그 다음 SDUI 화면 페이지를 연다.
4. JSON의 각 `component` 가 실제 화면에서 어떤 블록으로 렌더링되는지 비교해 본다.

즉, 아래처럼 대응해서 보면 된다.

- `metric-grid` -> 상단 핵심 지표 카드
- `table` -> 정합성 경고 표, API 흐름 표
- `timeline` -> 최근 거래 흐름
- `fact-list` -> SDUI 구조 메모
- `action-list` -> 운영 액션 버튼

## 6. 왜 JSON을 먼저 보는 것이 중요한가

일반적인 프론트엔드에서는 보통 화면부터 보고, 그 뒤에 데이터 API를 본다.
하지만 SDUI는 반대로 보는 것이 더 좋다.

이유는 SDUI의 핵심이 아래이기 때문이다.

- 서버가 화면 구조를 설명한다.
- 클라이언트는 그 설명을 그린다.

즉, JSON을 먼저 보면 "서버가 무엇을 결정했는가" 가 보이고,
화면을 그 다음에 보면 "브라우저가 그것을 어떻게 렌더링했는가" 가 보인다.

## 8. 브라우저에서 어디를 보면 좋은가

브라우저 개발자도구를 열 수 있다면 아래를 같이 보면 학습에 도움이 된다.

### 8.1 Network 탭

`/api/v1/admin/screens/core-banking-overview` 요청을 보면 된다.
이 요청의 응답 본문이 바로 SDUI 화면 정의 JSON이다.

### 8.2 Elements 탭

JSON에서 정의된 블록이 실제 HTML로 어떻게 바뀌었는지 볼 수 있다.

예를 들어:

- 서버 JSON의 `table`
- 브라우저 DOM 의 `<table>`

이 대응 관계를 보면 SDUI가 더 선명해진다.

### 8.3 Console 탭

필요하면 `app.js` 렌더링 흐름을 따라가면서 `screen.blocks` 가 어떻게 처리되는지 볼 수 있다.

## 9. 실행이 안 될 때 먼저 볼 것

### 9.1 포트 충돌

이미 `8080` 포트를 다른 프로그램이 쓰고 있으면 실행이 안 될 수 있다.
그 경우 아래처럼 다른 포트로 띄울 수 있다.

```powershell
.\gradlew.bat :bootstrap:bootRun --args="--server.port=18080"
```

그 뒤에는 주소도 `8080` 대신 `18080` 으로 바꾸면 된다.

### 9.2 빌드나 의존성 문제 확인

먼저 아래 명령으로 컴파일과 테스트가 통과하는지 본다.

```powershell
.\gradlew.bat test
```

### 9.3 보안 접근 문제

현재는 학습용 설정으로 모든 요청을 허용하고 있다.
즉, 지금 단계에서 화면 접근이 막힌다면 보통은 보안 정책보다 실행 실패나 포트 문제일 가능성이 더 크다.
