# 작업 기록

## 1. 작업명

- 그래들 래퍼 추가와 빌드 검증

## 2. 이번 작업에서 한 일

- Gradle Wrapper 파일을 프로젝트에 추가했다.
- 실제로 `.\gradlew.bat test` 를 실행해 전체 모듈이 컴파일되는지 확인했다.
- 빌드 성공 결과를 확인했다.
- `.temp/` 임시 경로를 Git 제외 대상으로 추가했다.
- 이번 작업의 의미를 설명하는 문서를 작성했다.

## 3. 왜 이 작업을 했는지

- 지금까지는 로컬에 `gradle` 명령이 없어 실제 빌드를 돌려보지 못했기 때문이다.
- 기능을 더 추가하기 전에 현재 프로젝트가 실제로 컴파일 가능한지 검증할 필요가 있었다.
- 이후 변경을 더 안전하게 하려면 재현 가능한 빌드 환경이 먼저 필요했다.

## 4. 어떻게 작업했는지

- 임시로 Gradle 배포본을 받아 Wrapper 를 생성했다.
- Wrapper 생성 후 `.\gradlew.bat test` 를 실행했다.
- 전체 모듈 컴파일이 성공하는지 확인했다.
- 임시 폴더 삭제를 시도했으나 일부 파일이 잠겨 있어 완전 삭제는 되지 않았고, 대신 `.gitignore` 에 제외 규칙을 추가했다.

## 5. 어디에 반영했는지

- Wrapper 스크립트: `gradlew`, `gradlew.bat`
- Wrapper 설정: `gradle/wrapper/`
- Git 제외 규칙: `.gitignore`
- 설명 문서: `docs/09-그래들-래퍼와-빌드-검증-설명.md`
- 현재 작업 기록: `docs/작업기록/2026-04-03-10-그래들-래퍼와-빌드-검증.md`

## 6. 학습 포인트

- Gradle Wrapper 는 로컬 Gradle 설치 없이도 같은 버전으로 빌드할 수 있게 해 준다.
- 빌드 성공은 프로젝트 구조와 코드 연결이 실제로 맞는다는 중요한 신호다.
- 멀티모듈 프로젝트는 문서뿐 아니라 빌드로도 계속 검증해야 한다.
- 개발 중 생기는 임시 폴더는 Git 제외 규칙으로 관리하는 것이 좋다.
