# 작업 기록

## 1. 작업명

- JPA 구현체와 거래 반영 처리기 작성

## 2. 이번 작업에서 한 일

- 계좌계 저장소의 Spring Data JPA 구현체와 어댑터 클래스를 작성했다.
- 거래계 저장소의 Spring Data JPA 구현체와 어댑터 클래스를 작성했다.
- `TransactionPostingProcessorImpl` 을 만들어 입금, 출금, 이체의 실제 엔트리, 원장, 잔액 반영 흐름을 구현했다.
- `AccountBalance` 엔티티에 입금과 출금 메서드를 추가했다.
- `TransferApplicationService` 가 거래를 먼저 저장한 뒤 반영하고 완료 상태로 바꾸는 흐름으로 보강했다.
- 이번 구조를 설명하는 한글 문서를 작성했다.

## 3. 왜 이 작업을 했는지

- 인터페이스와 스켈레톤만으로는 실제 동작이 되지 않기 때문이다.
- 저장소는 실제 DB 구현과 연결되어야 하고, 서비스는 실제 거래 반영 로직과 연결되어야 한다.
- 코어 뱅킹 구조에서 거래 헤더, 엔트리, 원장, 잔액의 연결을 실제 코드로 만들어 볼 필요가 있었다.

## 4. 어떻게 작업했는지

- 도메인 저장소 인터페이스는 유지하고, 인프라 계층에 Spring Data JPA 구현체를 만들었다.
- `AccountBalance` 잠금 조회는 `PESSIMISTIC_WRITE` 로 구현했다.
- 포스팅 처리기는 입금, 출금, 이체별로 잔액 변경과 엔트리/원장 생성 로직을 나누어 구현했다.
- 서비스는 거래를 먼저 저장해서 거래 식별자를 확보한 뒤 포스팅하도록 순서를 조정했다.

## 5. 어디에 반영했는지

- 계좌계 인프라 구현: `account-domain/src/main/java/com/bankingsystem/account/infrastructure/`
- 거래계 인프라 구현: `transaction-domain/src/main/java/com/bankingsystem/transaction/infrastructure/`
- 포스팅 처리기 구현: `transfer-domain/src/main/java/com/bankingsystem/transfer/infrastructure/posting/TransactionPostingProcessorImpl.java`
- 설명 문서: `docs/JPA-구현체와-거래-반영-처리기-설명.md`
- 현재 작업 기록: `docs/작업기록/2026-04-03-07-JPA-구현체와-반영-처리기.md`

## 6. 학습 포인트

- 도메인 인터페이스와 기술 구현을 분리하면 구조가 더 유연해진다.
- Spring Data JPA는 저장소 구현을 빠르게 연결하는 데 유용하다.
- 동시성 제어가 필요한 조회는 잠금 조회가 필요할 수 있다.
- 거래 반영은 단순 저장이 아니라 잔액, 엔트리, 원장이 함께 움직이는 흐름이다.
- 서비스와 반영 처리기를 분리하면 각 클래스의 책임이 더 분명해진다.
