# 작업 기록

## 1. 작업명

- 문서 읽기 순서와 파일명 체계 정리

## 2. 이번 작업에서 한 일

- 설명 문서 파일명에 번호를 붙여 읽는 순서가 바로 보이도록 정리했다.
- 아키텍처 문서를 작업기록 폴더 밖으로 이동해 설명 문서 영역으로 분리했다.
- `docs/00-문서-읽기-순서.md` 를 만들어 전체 문서 추천 읽기 순서를 정리했다.
- `docs/작업기록/00-작업기록-목차.md` 를 만들어 작업기록 추적 순서를 정리했다.
- 작업기록 가이드와 양식 파일명도 앞쪽 번호가 보이도록 조정했다.

## 3. 왜 이 작업을 했는지

- 기존에는 파일명만으로 문서 성격과 읽는 순서를 파악하기 어려웠기 때문이다.
- 처음 따라오는 사람이 어느 문서부터 읽어야 하는지 바로 보이게 만들 필요가 있었다.
- 설명 문서와 작업기록의 역할을 더 명확히 나눌 필요가 있었다.

## 4. 어떻게 작업했는지

- 설명 문서는 `00`, `01`, `02` 같은 번호형 파일명으로 정리했다.
- 작업기록은 날짜와 순번 체계를 유지하되, 별도 목차 문서를 추가했다.
- 읽기 순서를 설명하는 문서를 새로 만들어 문서별 의미와 추천 읽기 순서를 함께 적었다.

## 5. 어디에 반영했는지

- 전체 문서 읽기 순서: `docs/00-문서-읽기-순서.md`
- 작업기록 목차: `docs/작업기록/00-작업기록-목차.md`
- 번호형 설명 문서들: `docs/01-...` 부터 `docs/07-...` 까지
- 현재 작업 기록: `docs/작업기록/2026-04-03-08-문서-읽기-순서-정리.md`

## 6. 학습 포인트

- 문서도 코드처럼 구조와 네이밍 규칙이 중요하다.
- 설명 문서와 작업기록은 역할이 다르므로 분리하는 편이 좋다.
- 번호형 파일명은 문서의 읽는 순서를 직관적으로 보여주는 장점이 있다.

## 7. 다음에 이어서 할 일

- 이후 새 설명 문서가 생기면 계속 번호형 파일명으로 추가
- 이후 작업기록은 기존 날짜와 순번 체계 유지
