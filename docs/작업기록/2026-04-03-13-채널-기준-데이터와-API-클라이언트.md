# 작업 기록

## 1. 작업명

- 채널 기준 데이터와 API 클라이언트 식별 구조 추가

## 2. 이번 작업에서 한 일

- `channel-security` 모듈에 `Channel`, `ApiClient` 엔티티를 추가했다.
- 채널 상태, 채널 유형, API 클라이언트 상태 enum 을 추가했다.
- 채널 코드와 클라이언트 키로 조회하는 저장소 인터페이스와 JPA 구현체를 만들었다.
- `ChannelIdentityResolver` 를 만들어 채널 코드와 클라이언트 키를 실제 DB 기준 데이터와 연결했다.
- `channel-api` 가 `channel-security` 모듈을 참조하도록 의존성을 추가했다.
- API 요청 로그 저장 시 더 이상 `channelId = 1` 을 쓰지 않고, 기준 데이터 조회 결과를 쓰도록 바꿨다.
- `X-Api-Client-Key` 헤더 상수를 추가했다.
- `OPEN_API` 채널과 기본 API 클라이언트 시드 SQL 파일을 추가했다.
- 리졸버 테스트를 작성하고 전체 테스트를 다시 통과시켰다.
- 이번 작업의 원리와 이유를 설명하는 문서를 작성했다.

## 3. 왜 이 작업을 했는지

- 하드코딩된 채널 ID 는 구조적으로 오래 유지하면 안 되는 임시 코드이기 때문이다.
- `channel`, `api_client` 는 기준 데이터이므로 실제 코드에서도 기준 데이터처럼 다뤄야 하기 때문이다.
- API 요청 이력을 더 현실적인 운영 구조로 만들려면 어떤 채널과 어떤 호출 주체인지 연결할 수 있어야 하기 때문이다.
- 이후 인증과 인가를 붙이기 전에 식별 구조를 먼저 세우는 것이 단계적으로 자연스럽기 때문이다.

## 4. 어떻게 작업했는지

### 4.1 기준 데이터 모델을 먼저 만들었다

- `channel-security` 모듈에 채널과 API 클라이언트 엔티티를 추가했다.
- 두 엔티티는 모두 다른 이력 데이터가 참조하는 기준점이므로 기준 데이터 모델로 두었다.

### 4.2 조회 규칙을 리졸버로 분리했다

- 인터셉터가 저장소를 직접 조합하지 않도록 `ChannelIdentityResolver` 를 만들었다.
- 이 리졸버가 채널 코드와 클라이언트 키를 받아 `channelId`, `apiClientId` 로 바꾼다.

### 4.3 요청 로그 저장 흐름을 하드코딩에서 조회 기반으로 바꿨다

- 이전에는 `OPEN_API_CHANNEL_ID = 1` 을 사용했다.
- 이제는 `OPEN_API` 코드로 실제 채널을 조회하고, 선택적으로 API 클라이언트도 조회한다.

### 4.4 기준 데이터 시드도 같이 준비했다

- 기준 데이터를 조회하는 코드가 생겼기 때문에 최소 시드 SQL 도 같이 만들었다.
- `OPEN_API` 채널과 기본 API 클라이언트가 DB에 없으면 요청 이력 구조가 동작할 수 없기 때문이다.

## 6. 이번 작업에서 중요했던 판단

### 6.1 채널은 코드로, PK 는 내부 식별자로 다뤘다

- 코드에서는 `OPEN_API` 같은 업무 코드를 기준으로 사용했다.
- 숫자 PK 는 DB 내부 식별자로만 취급했다.

### 6.2 API 클라이언트는 현재 단계에서 식별까지만 했다

- `X-Api-Client-Key` 를 읽어 DB와 연결은 하지만, 아직 인증 실패로 차단하지는 않는다.
- 이번 단계의 목적은 인증 완성이 아니라 구조 준비이기 때문이다.

### 6.3 보안 관련 기준 데이터는 channel-security 로 모았다

- 웹 계층인 `channel-api` 와 식별/보안 기준인 `channel-security` 의 책임을 나눴다.
- 앞으로 인증, 인가, 키 검증을 붙일 때 확장하기 쉬운 구조를 선택했다.

## 7. 학습 포인트

- 기준 데이터는 숫자 ID 가 아니라 업무 코드로 연결하는 편이 유지보수에 유리하다.
- 식별과 인증은 다르며, 식별 구조를 먼저 세우면 보안 구조를 단계적으로 붙이기 쉽다.
- 인터셉터가 저장소를 직접 조합하기보다 리졸버 서비스로 분리하면 역할이 선명해진다.
- 기준 데이터를 코드에서 참조하기 시작하면 시드 데이터 관리도 같이 고려해야 한다.
- 모듈 분리는 단순 폴더 나누기가 아니라 책임을 어디에 둘지 결정하는 작업이다.
