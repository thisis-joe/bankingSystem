# 작업 기록

## 1. 작업명

- 스프링부트 멀티모듈 뼈대 구성

## 2. 이번 작업에서 한 일

- Gradle 기반 멀티모듈 프로젝트 구조를 만들었다.
- 루트에 `settings.gradle`, `build.gradle`, `gradle.properties`, `.gitignore` 를 추가했다.
- `common`, `account-domain`, `transaction-domain`, `transfer-domain`, `interest-domain`, `channel-api`, `channel-security`, `information-read`, `batch`, `bootstrap` 모듈을 추가했다.
- 각 모듈에 기본 `build.gradle` 을 만들고 의존 관계를 정리했다.
- `bootstrap` 모듈에 Spring Boot 실행 클래스와 `application.yml` 을 만들었다.
- 모듈 역할을 설명하는 한글 문서를 작성했다.

## 3. 왜 이 작업을 했는지

- DDL 다음 단계로 실제 백엔드 프로젝트 구조가 필요했기 때문이다.
- 코어 뱅킹은 기능이 많아질수록 코드가 쉽게 섞이므로, 처음부터 책임별 모듈 분리가 중요하다.
- 이후 엔티티, 저장소, 서비스, 컨트롤러를 넣을 때 어디에 두어야 하는지 기준을 먼저 만들 필요가 있었다.

## 4. 어떻게 작업했는지

- 루트 Gradle 설정에서 공통 빌드 규칙을 한 번에 관리하도록 구성했다.
- Java 21 toolchain 과 Spring Boot 의존성 BOM을 루트 기준으로 통일했다.
- 실행 모듈인 `bootstrap` 과 재사용 모듈들을 분리했다.
- 각 모듈에는 지금 단계에서 구조 확인이 가능하도록 기본 자바 클래스를 하나씩 넣었다.
- 설명 문서에서는 루트 파일 역할, 모듈 책임, MVC와의 연결 관계를 한글로 정리했다.

## 5. 어디에 반영했는지

- 루트 설정: `settings.gradle`, `build.gradle`, `gradle.properties`, `.gitignore`
- 모듈 빌드 파일: 각 모듈의 `build.gradle`
- 실행 시작점: `bootstrap/src/main/java/com/bankingsystem/bootstrap/BankingSystemApplication.java`
- 실행 설정: `bootstrap/src/main/resources/application.yml`
- 설명 문서: `docs/스프링부트-멀티모듈-뼈대-설명.md`
- 현재 작업 기록: `docs/작업기록/2026-04-03-03-모듈-뼈대-구성.md`

## 6. 학습 포인트

- 멀티모듈은 마이크로서비스와 다르며, 한 프로젝트 안에서 책임을 분리하는 방법이다.
- `settings.gradle` 은 프로젝트 구성표이고, 루트 `build.gradle` 은 공통 빌드 규칙이다.
- 모듈별 `build.gradle` 은 각 모듈이 누구에게 의존하는지 보여준다.
- 실행 가능한 Spring Boot 애플리케이션은 보통 하나의 진입 모듈에 두는 편이 이해하기 쉽다.
- MVC 구조만으로는 부족하고, 도메인 분리와 기술 역할 분리를 함께 봐야 대형 시스템을 이해할 수 있다.
