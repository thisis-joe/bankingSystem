# 작업 기록

## 1. 작업명

- 거래계 핵심 엔티티 작성

## 2. 이번 작업에서 한 일

- `transaction-domain` 모듈에 거래 관련 enum 을 추가했다.
- `BankTransaction`, `TransactionEntry`, `AccountLedger` 엔티티를 작성했다.
- 거래 헤더와 거래 엔트리, 계좌 원장의 역할 차이를 설명하는 한글 문서를 작성했다.

## 3. 왜 이 작업을 했는지

- 계좌계 엔티티만으로는 실제 자금 이동과 거래 이력을 표현할 수 없기 때문이다.
- 입금, 출금, 이체 서비스를 만들기 전에 거래 모델을 먼저 세워야 원장 기반 구조를 유지할 수 있다.
- 코어 뱅킹에서는 현재 잔액보다 거래 이력과 원장 구조가 더 핵심이기 때문이다.

## 4. 어떻게 작업했는지

- 거래의 업무 정체성을 표현하는 `BankTransaction` 을 만들었다.
- 실제 자금 반영 줄을 표현하는 `TransactionEntry` 를 만들었다.
- 계좌 중심 원장 흐름을 표현하는 `AccountLedger` 를 만들었다.
- 상태와 유형값은 enum 으로 분리해 문자열 오타를 줄이도록 했다.
- JPA 관계는 거래 기준과 계좌 기준을 모두 표현할 수 있도록 잡았다.

## 5. 어디에 반영했는지

- 거래 엔티티 패키지: `transaction-domain/src/main/java/com/bankingsystem/transaction/domain/model/`
- 설명 문서: `docs/거래계-엔티티-설명.md`
- 현재 작업 기록: `docs/작업기록/2026-04-03-05-거래계-엔티티.md`

## 6. 학습 포인트

- 거래 헤더와 거래 엔트리는 서로 다른 개념이다.
- 하나의 업무 거래가 여러 계좌 반영 줄로 나뉠 수 있다.
- 원장 구조는 거래 중심과 계좌 중심을 나눠서 보는 것이 중요하다.
- enum 을 잘 나누면 상태값과 유형값의 의미가 더 명확해진다.
- JPA 관계는 단순 문법이 아니라 도메인 구조를 코드로 옮기는 작업이다.
