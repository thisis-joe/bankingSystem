# 작업 기록

## 1. 작업명

- 공통 감사필드와 계좌계 핵심 엔티티 작성

## 2. 이번 작업에서 한 일

- `common` 모듈에 공통 감사필드용 `BaseEntity` 를 추가했다.
- `common` 모듈에 금액 타입 `Money` 를 추가했다.
- `account-domain` 모듈에 고객, 상품, 계좌, 계좌 소유 관계, 계좌 잔액 엔티티를 작성했다.
- 상태값과 유형값을 위한 enum 들을 함께 만들었다.
- 왜 이렇게 나누었는지 설명하는 한글 문서를 작성했다.

## 3. 왜 이 작업을 했는지

- DDL 구조를 실제 JPA 엔티티로 옮기기 시작해야 다음 단계로 갈 수 있기 때문이다.
- 공통 필드는 모든 엔티티에 반복되므로 먼저 추상화하는 편이 좋다.
- 코어 뱅킹에서는 고객, 상품, 계좌, 현재 잔액의 구조가 먼저 안정되어야 이후 거래 로직이 자연스럽게 올라간다.

## 4. 어떻게 작업했는지

- 공통 모듈에 `created_at`, `updated_at` 을 자동 관리하는 `BaseEntity` 를 만들었다.
- 금액은 도메인에서 안전하게 다루기 위해 `Money` 값 객체를 만들었다.
- 계좌 도메인에서는 JPA 관계를 먼저 명확히 표현했다.
- `AccountBalance` 는 계좌와 기본 키를 공유하는 구조라 `@MapsId` 로 매핑했다.
- 잔액 엔티티에는 동시성 제어를 염두에 두고 `@Version` 을 추가했다.

## 5. 어디에 반영했는지

- 공통 감사필드: `common/src/main/java/com/bankingsystem/common/persistence/BaseEntity.java`
- 금액 타입: `common/src/main/java/com/bankingsystem/common/money/Money.java`
- 계좌 엔티티 패키지: `account-domain/src/main/java/com/bankingsystem/account/domain/model/`
- 설명 문서: `docs/공통-감사필드와-계좌계-엔티티-설명.md`
- 현재 작업 기록: `docs/작업기록/2026-04-03-04-공통필드와-계좌계-엔티티.md`

## 6. 학습 포인트

- 공통 필드는 추상 클래스나 기반 클래스로 빼서 중복을 줄일 수 있다.
- 금액은 단순 숫자가 아니라 값 객체로 다루면 더 안전하다.
- JPA 관계 매핑은 DB의 PK, FK 구조를 코드에서 표현하는 작업이다.
- `@MapsId` 는 기본 키와 외래 키를 동시에 쓰는 일대일 구조에서 자주 사용된다.
- `@Version` 은 낙관적 락의 출발점이다.
- 엔티티를 먼저 만들고 그 위에 저장소와 서비스를 쌓는 순서가 구조 이해에 유리하다.
