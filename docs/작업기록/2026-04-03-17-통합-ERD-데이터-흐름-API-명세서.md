# 작업 기록

## 1. 작업명

- 통합 ERD, 데이터 흐름, API 명세 문서 작성

## 2. 이번 작업에서 한 일

- 현재 DDL과 코드 기준으로 핵심 테이블 관계를 다시 정리했다.
- 고객/계좌/상품, 거래/원장, 채널/요청 로그, 자동이체/이자 확장 영역으로 나누어 ERD를 정리했다.
- 입금, 출금, 이체, 멱등 처리, 요청 추적, SDUI 운영 콘솔의 데이터 흐름을 단계별로 정리했다.
- 현재 구현된 API 목록과 각 요청/응답 구조, 공통 헤더, 오류 코드 체계를 한 문서로 정리했다.
- 현재 구현된 영역과 DDL만 준비된 영역을 구분해서 설명했다.
- 길고 자세한 단일 설명 문서를 새로 만들었다.

## 3. 왜 이 작업을 했는지

- 사용자가 프로젝트 전체 구조를 한 번에 보는 문서를 원했기 때문이다.
- 기존 문서는 주제별로 나뉘어 있어, ERD와 데이터 흐름과 API 명세를 한눈에 연결해서 보기에는 분산되어 있었기 때문이다.
- follow up 과 변경 작업을 할 때, 현재 시스템의 전체 지도를 보는 문서가 있으면 훨씬 편하기 때문이다.

## 4. 어떻게 작업했는지

- 먼저 실제 DDL을 기준으로 테이블과 관계를 다시 확인했다.
- 그 다음 현재 구현된 컨트롤러, 요청/응답 DTO, 예외 응답 구조를 다시 확인했다.
- 마지막으로 "현재 구현" 과 "설계 준비" 상태를 명확히 구분해 오해가 생기지 않도록 작성했다.

## 6. 학습 포인트

- ERD는 테이블 목록만 보는 것이 아니라 데이터 성격과 관계를 함께 봐야 한다.
- 데이터 흐름은 서비스 메서드와 테이블 반영 순서를 같이 이해해야 한다.
- API 명세는 요청/응답뿐 아니라 헤더, 오류 코드, 추적 정보까지 같이 봐야 한다.
- 구현된 영역과 설계만 준비된 영역을 구분해서 보는 습관이 중요하다.
