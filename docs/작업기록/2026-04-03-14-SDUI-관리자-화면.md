# 작업 기록

## 1. 작업명

- SDUI 기반 코어 뱅킹 관리자 화면 추가

## 2. 이번 작업에서 한 일

- `information-read` 모듈에 운영 대시보드용 읽기 모델과 샘플 데이터를 만들었다.
- `channel-api` 모듈에 SDUI 화면 정의 JSON을 만드는 서비스를 추가했다.
- `/api/v1/admin/screens/core-banking-overview` API를 추가했다.
- `bootstrap` 정적 리소스에 SDUI 렌더러 페이지를 만들었다.
- 한 페이지 안에서 핵심 지표, 정합성 경고, 거래 흐름, API 흐름, SDUI 구조 설명, 액션 블록을 모두 볼 수 있도록 구성했다.
- 실행 모듈에 H2 런타임 DB 설정을 추가해 애플리케이션이 바로 뜰 수 있게 했다.
- 실행 모듈에 JPA 엔티티/리포지토리 스캔 범위를 명시했다.
- `channel-security` 에 학습용 보안 설정을 추가해 SDUI 화면 접근이 가능하도록 했다.
- 실제 실행 후 SDUI JSON API와 정적 페이지가 모두 200 응답하는 것까지 확인했다.
- 이번 작업의 개념과 원리를 설명하는 문서를 작성했다.

## 3. 왜 이 작업을 했는지

- 사용자가 JSON 기반 프론트엔드와 SDUI 개념 자체를 이해하고 싶다고 했기 때문이다.
- 코어 뱅킹 운영 화면은 관리자 성격이 강하므로 SDUI 예제를 만들기에 적합했기 때문이다.
- 프론트엔드 기술 자체보다 서버가 화면 구조를 어떻게 설명하는지 보여 주는 것이 이번 학습 목표에 더 맞기 때문이다.
- 한 페이지 안에서 모든 것을 보는 시스템형 관리자 화면이 운영 구조 이해에도 도움이 되기 때문이다.

## 4. 어떻게 작업했는지

### 4.1 데이터, 화면 정의, 렌더러를 분리했다

- 읽기 모델 데이터는 `information-read`
- 화면 정의 JSON 조립은 `channel-api`
- 실제 HTML 렌더링은 `bootstrap/static`

이렇게 나눈 이유는 SDUI의 핵심이 `서버가 화면을 설명하고 클라이언트가 렌더링만 한다` 는 점을 구조적으로 보여 주기 위해서다.

### 4.2 관리자 화면에 맞는 블록형 JSON 구조를 만들었다

- metric-grid
- table
- timeline
- fact-list
- action-list

이 다섯 가지 컴포넌트를 지원하도록 만들었다.
브라우저는 `component` 값을 보고 어떤 HTML을 그릴지 결정한다.

### 4.3 화면은 한 페이지 운영 관제판 형태로 설계했다

- 상단: 핵심 운영 지표
- 중단: 정합성 경고, 최근 거래 흐름, 최근 API 흐름
- 하단: SDUI 구조 설명, 운영 액션

즉, 운영자가 빠르게 상황을 읽고 판단할 수 있는 구조를 우선했다.

### 4.4 실행 가능 상태까지 같이 맞췄다

- H2 런타임 DB 추가
- JPA 스캔 범위 명시
- Spring Security 학습용 허용 설정 추가

단순히 파일만 만드는 것이 아니라 실제로 실행 가능한 상태까지 확인했다.

## 5. 어디에 반영했는지

- 읽기 모델 서비스: `information-read/src/main/java/com/bankingsystem/information/read/application/service/CoreBankingOverviewReadService.java`

- SDUI 화면 정의 서비스: `channel-api/src/main/java/com/bankingsystem/channel/api/application/service/CoreBankingAdminScreenService.java`
- SDUI API: `channel-api/src/main/java/com/bankingsystem/channel/api/presentation/controller/AdminScreenController.java`

- 정적 스타일: `bootstrap/src/main/resources/static/sdui-admin/styles.css`
- 정적 렌더러 JS: `bootstrap/src/main/resources/static/sdui-admin/app.js`
- 실행 모듈 설정: `bootstrap/build.gradle`
- 애플리케이션 설정: `bootstrap/src/main/resources/application.yml`
- JPA 스캔 설정: `bootstrap/src/main/java/com/bankingsystem/bootstrap/BankingSystemApplication.java`
- 학습용 보안 설정: `channel-security/src/main/java/com/bankingsystem/channel/security/config/ChannelSecurityConfig.java`
- 설명 문서: `docs/13-SDUI-관리자-화면-설명.md`
- 현재 작업 기록: `docs/작업기록/2026-04-03-14-SDUI-관리자-화면.md`

## 6. 이번 작업에서 중요했던 판단

### 6.1 프론트는 얇게 두고 서버 설명을 두껍게 했다

- 이번 목표는 프론트 프레임워크 학습이 아니라 SDUI 원리 이해였다.
- 그래서 브라우저는 범용 렌더러 역할만 하게 두었다.

### 6.2 화면도 읽기 모델의 일부처럼 다뤘다

- 운영 대시보드는 쓰기 모델보다 읽기 모델이 중요하다.
- 서버가 어떤 블록을 어떤 순서로 보여 줄지까지 결정하도록 했다.

### 6.3 실행 확인까지 포함했다

- `test` 성공만으로 끝내지 않고 실제 HTTP 200 응답까지 확인했다.
- SDUI는 특히 런타임에서 확인하는 것이 중요하기 때문이다.

## 7. 학습 포인트

- SDUI는 서버가 화면 구조를 JSON으로 내려주고 클라이언트는 그것을 렌더링하는 방식이다.
- 관리자 화면은 정보 구조와 정책 변화가 잦아 SDUI와 잘 맞는다.
- SDUI를 이해하려면 `데이터`, `화면 정의`, `렌더러` 를 분리해서 봐야 한다.
- Spring Boot 정적 리소스와 API를 같이 두면 SDUI 학습용 예제를 만들기 좋다.
- 실행 모듈에서는 컴포넌트 스캔뿐 아니라 엔티티와 리포지토리 스캔 범위도 중요하다.
